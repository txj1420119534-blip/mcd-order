# 麦麦试玩第二轮：实施与验收计划

日期：2026-10-23（Asia/Singapore）。本轮以用户已验收的第一版为基础，保留三个独立仓库与既有业务规则。

## 用户目标

1. 点餐直接进入选餐任务，补齐商品详情、购物袋、任务领取、差额提醒、奖励说明与模拟结算弹窗。
2. 采用更接近麦当劳点餐及活动产品的红、金、白层级和简短中文文案，以完整图片代替主要食物、场景和角色的几何插图。
3. 保留统一试玩包，并尝试提供可直接打开的在线网站；MCP 只在实际调用成功且契约验证后才能标为实时。

## 统一设计约束

- 基础色：金黄 `#FFC72C`、红 `#DA291C`、墨黑 `#27251F`，使用白色与浅暖灰作为内容底色。
- 电脑与手机均优先显示主要任务；标题和商品文案采用短句，技术细节收进“规则与来源”。
- 按钮、选择状态、价格、进度与错误状态直接可见，不依赖悬停。底部操作栏不得遮住主要内容。
- 食物、聚会与游戏对象使用本轮生成的 raster 图片。Canvas 可继续承载游戏运行，但主要角色与目标通过 `drawImage` 使用图片，不以线条和色块替代完成稿。
- 图片来源、完整生成提示词和哈希保留在各仓库素材记录。当前图像工具未提供模型版本选择参数，不声明已指定某个模型版本。
- 保留简短“体验版”身份与模拟操作标签；重复长说明收纳到详情，不删除历史日期、券条件、适用范围或失败信息。

## 三项目实施边界

### 点餐助手

沿用当前定价和优惠规则。金卡门槛、配送费、商品券、任务领取顺序与未来券分开解释。差额提醒按实际计算结果生成，用户可以保持原单继续，不自动添加商品或强制凑单。

### 派对策划

保留主题、菜单、流程和结果四步及已有预算/人数规则，缩短进入策划的路径。成人聚会是本地方案；真实官方儿童商品保持原适用范围，不作成人可订承诺。

### 游乐局

保留合成、营救和推理三款游戏的实际规则及 88 模拟积分、周期和幂等奖励逻辑。改进素材、层次、命中/合成反馈、暂停、重试和结算，不按游戏名称重新设计规则。

## 验收

各仓分别运行现有业务测试、R2 测试、交付测试和构建；派对额外运行 check。补充新逻辑与交互验收，保留真实命令输出。

使用实际 Chromium/Playwright 测试桌面、390px 与 320px 页面，核对图片加载、按钮反馈、弹窗焦点与关闭、完整任务流程、重置、存储禁用和导入失败。检查自包含包及静态 HTTP 包；图片由实际截图验收，不将单元测试视为视觉验收。

## 当前证据与限制

当前工具清单未暴露麦当劳业务 MCP 调用，也未提供 Sites/Vercel 部署工具。官方 `M-China/mcd-mcp-server` README 已只读取得，列出结构化业务数据与部分图片字段，未列出完整官方页面或弹窗截图的导出工具。官方页面读取受网络代理限制，不能声称已对照当前真实点餐页面截图。

GitHub Git 传输可用，但 GitHub API/Pages 域名的检查受网络代理阻碍。发布目标正在确认，完成实际上传与网页打开验证后才可宣称在线交付完成。
