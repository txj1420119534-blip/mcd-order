# 统一入口与可复现交付

本轮统一入口独立位于 `scripts/entry-page.mjs`，三个项目源码仍各自在原仓库维护。交付脚本只收拢已经独立构建的结果，没有合并项目源码或引入 npm 依赖。

## 入口与图片

入口采用红、金、奶油白三张卡片，分别进入点餐、聚会与游乐局。手机上卡片依次排列，按钮始终可见，不依赖鼠标悬停。体验身份与模拟边界在页脚及“关于体验”中可见。

- 点餐：沿用上一轮原创 `mcd-order/assets/order-hero.png`。
- 聚会：本轮新生成的 `mcd-party/assets/party-birthday-v2.png`。
- 游乐局：本轮新生成的 `mcd-games/assets/game-stage-v2.png` 和透明餐品图集 `game-food-atlas-v2.png`。

三张入口主视觉均为实际 PNG，游乐局叠加元素也是 PNG 图集中的餐品，未用 SVG 线稿替代。实际采用路径与图片 SHA256 记录于交付外层的 `测试/entry-art.json`。各项目的第一轮及第二轮 AI 图片来源记录均随试玩包保留，不把旧图描述成本轮新生成。

## 两种交付

- `麦麦项目试玩/`：统一入口和三个项目为自包含单文件网页，内联脚本与图片。无需安装 Node、登录或输入 Key。目标电脑实际 `file://` 双击仍待手测；云环境的管理策略阻断与断网内容测试必须分别理解。
- `静态HTTPS/`：四个入口加各项目独立模块和 PNG 资源，可部署在站点根路径或项目子路径。入口图片采用包内相对路径以便并行加载和缓存，没有外部 CDN。
- `GitHub-Pages待发布/docs/`：与静态构建对应的本地待发布目录，共 61 文件、28,218,099 字节；校验表位于上层 `PUBLIC_MANIFEST.json`。准备目录不代表已经部署，实际托管能力见《托管与MCP实测》。

正常打包会同时核对构建清单中的源码、构建脚本及 HTTP 输出哈希，拒绝复制陈旧源码或被修改的输出。最终 ZIP 包含精简 Markdown 报告与最终截图；基线、失败截图及原始日志留在交付外层。

## 已完成的打包检查

`entry.test.mjs` 与 `verify-build.test.mjs` 共 5 项测试全部通过，覆盖三入口相对链接、本地 PNG、模拟声明、离线资源边界，以及陈旧构建和输出变化的显式拒绝。统一入口还在 1440、390、320 像素视口实际运行，检查图片加载、横向溢出、三入口、说明弹窗及 Escape 关闭，无脚本错误。

完整项目流程、最终截图和两个交付方式的验收以本轮统一浏览器报告为准。这些脚本检查不替代真实视觉审阅，也不证明目标电脑双击已通过。

## 复现

```sh
node /workspace/试玩交付-v2/scripts/build-package.mjs --skip-build --zip
python3 /workspace/试玩交付-v2/scripts/zip-package.py /workspace/试玩交付-v2/静态HTTPS /workspace/试玩交付-v2/静态HTTPS构建包.zip
node /workspace/试玩交付-v2/scripts/prepare-pages.mjs
```

`--skip-build` 仅用于三仓已经完成并通过校验的构建。脚本不创建提交、不推送、不启用 Pages，也不执行任何真实 MCP 业务操作。图片来源、官方声明和历史快照/模拟边界均保留。
